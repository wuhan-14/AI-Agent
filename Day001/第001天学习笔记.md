## 一、动手：3 个任务的参考答案

### 任务 1｜两门语言各写一个 HelloWorld，命令行和 IDE 各跑一次

**Java**（存为 `Hello.java`）

```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Java");
        System.out.println("JDK 版本: " + System.getProperty("java.version"));
    }
}
```

```bash
javac Hello.java && java Hello
```

应该看到：`Hello, Java / JDK 版本: 21.x`

**Python**（存为 `hello.py`）

```python
import sys

print("Hello, Python")
print("解释器版本:", sys.version.split()[0])
```

```bash
python hello.py
```

应该看到：`Hello, Python / 解释器版本: 3.11.x`

### 任务 2｜建 study/java 与 study/python 两个目录，分别放练习

```bash
mkdir -p study/java study/python study/notes
```
分目录的理由只有一个：两门语言的运行方式不同（`javac`/`java` vs `python`），混在一起最容易「改错文件」。再往下建议按天分：`study/java/day01/`、`study/python/day01/`，以后回看不用翻。

**加练（有时间再做）**：

1. 把 `println` 换成 `print`，再输出一次，看换行去哪了
2. 运行时加参数 `java Hello a b`，打印 `args.length`，确认参数从哪进来
3. 把类名改成 `HelloWorld`，先不改文件名编译，记下报错，再改名重跑

> 改代码比抄代码有用：抄只证明你会复制，改才证明你知道每一行控制什么。

## 三、今天只要记住这 3 句

1. JDK 是开发工具包（含编译器 javac），JRE 是运行环境（含 JVM 与类库），JVM 是真正执行字节码的虚拟机；三者是包含关系 JDK ⊃ JRE ⊃ JVM。
2. javac 把 `.java` 编译成 `.class` 字节码，java 负责启动 JVM 运行字节码；编译期只能发现语法与类型错误，空指针、数组越界这类问题只有在运行时才暴露。
3. 这是所有后续工作的前提：后面调模型 API、跑向量库、起 Spring Boot 服务，第一步都是确认 `java -version` / `python -V` 正常、环境变量没配错。

> 今天最容易踩的坑：PATH 里没有 JDK 的 bin 目录时，`javac` 会提示「不是内部或外部命令」，装完必须新开一个终端窗口。

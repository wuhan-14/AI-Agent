## 五、概念详解

### Java 线 · HashMap 与 Map 接口

#### 1. put/get/containsKey/remove

- **这是一组清单**：逐项过一遍，每项只回答两个问题——在哪配置、怎么验证它生效了。
- **落地**：做一张三列表：项目 / 我现在的做法 / 生产环境该怎么改。空着的就是明天要补的。
- **验证**：能说出少做其中哪一项，会引发什么故障。
- **今天的最低要求**：把这组清单里的每一项都能在自己机器上找到对应位置。

#### 2. 遍历 entrySet 与 keySet

- **这是对照型知识**：不要背定义，直接列一张表——左边写 A，右边写 B，比较「适用场景 / 代价 / 什么时候不能用」。
- **落地**：在「统计一段英文文本的词频并按次数排序输出前 10」里各用一次，让两者的差异产生可观察的结果。
- **验证**：能说出「如果我选错了会怎样」，说不出来就还没懂。

#### 3. computeIfAbsent 的常用场景

- **这是结论型知识**：这句话本身就是要记住的判断，重点是「为什么是这样」。
- **落地**：在今天的示例代码里找出对应的一行，把它注释掉再运行，观察差异。
- **验证**：想一个反例（什么情况下这句话不成立），想不出来说明理解还停留在表面。

#### 4. HashMap 无序、LinkedHashMap 保序

- **这是接口/注解型知识**：不用背签名。官方文档搜 `HashMap`，看清它接收什么、返回什么、什么时候不生效。
- **落地**：写一个最小调用（3–5 行）放进 `HashMap 与 Map 接口` 的练习里，跑通一次。
- **验证**：把参数改错或去掉注解，看报什么错。错误信息就是最好的文档。

## 九、卡住时的排查顺序

| 现象 | 最可能原因 | 第一步查什么 |
| --- | --- | --- |
| 程序起不来 / 报错 | HashMap 的 key 必须重写 hashCode/equals | 先读完整报错，找到第一个 `Caused by` 和自己写的类名 |
| 结果不对但不报错 | 输入不符合预期，或边界没处理 | 在关键位置打印中间值，确认数据在哪一步变错 |
| 照抄示例也跑不通 | 版本/依赖/环境不一致 | 对比版本号；用干净目录重跑一次 |
| 看不懂报错 | 英文术语不熟 | 把报错原文粘到搜索引擎，加上语言和框架名 |

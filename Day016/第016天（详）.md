## 五、概念详解

### Java 线 · StringBuilder、StringJoiner

#### 1. 循环拼接为什么慢（每次新建对象）

- **这是结论型知识**：这句话本身就是要记住的判断，重点是「为什么是这样」。
- **落地**：在今天的示例代码里找出对应的一行，把它注释掉再运行，观察差异。
- **验证**：想一个反例（什么情况下这句话不成立），想不出来说明理解还停留在表面。
- **今天的最低要求**：能指着 `StringBuilder、StringJoiner` 里的具体一行说清它在干什么。

#### 2. StringBuilder 的 append/toString

- **是什么**：可变的字符序列，拼接在同一个缓冲区里追加。
- **为什么重要**：循环拼接、SQL 拼装、日志拼装的标准做法，复杂度从 O(n²) 降到 O(n)。
- **怎么用 / 坑**：`sb.append(x)` 后 `sb.toString()`。它非线程安全，多线程用 StringBuffer。

#### 3. StringBuilder 与 StringBuffer 的区别

- **是什么**：可变的字符序列，拼接在同一个缓冲区里追加。
- **为什么重要**：循环拼接、SQL 拼装、日志拼装的标准做法，复杂度从 O(n²) 降到 O(n)。
- **怎么用 / 坑**：`sb.append(x)` 后 `sb.toString()`。它非线程安全，多线程用 StringBuffer。

#### 4. StringJoiner 的用法

- **这是接口/注解型知识**：不用背签名。官方文档搜 `StringJoiner`，看清它接收什么、返回什么、什么时候不生效。
- **落地**：写一个最小调用（3–5 行）放进 `StringBuilder、StringJoiner` 的练习里，跑通一次。
- **验证**：把参数改错或去掉注解，看报什么错。错误信息就是最好的文档。

### Python 线 · 字符串拼接与格式化

#### 1. + 与 join 的性能差异

- **是什么**：用分隔符把可迭代对象拼成一个字符串。
- **为什么重要**：比循环 `+=` 快得多，是 Python 拼接列表的标准写法。
- **怎么用 / 坑**：`",".join(["a","b"])`；元素必须都是 str，数字要先 map(str, ...)。
- **今天的最低要求**：能指着 `字符串拼接与格式化` 里的具体一行说清它在干什么。

#### 2. f-string 的格式说明符

- **是什么**：在字符串前加 f，用 `{表达式}` 直接嵌入变量与格式说明。
- **为什么重要**：比 `+` 拼接和 `%` 格式化更可读，也不容易漏空格。
- **怎么用 / 坑**：`f"{price:.2f}"` 保留两位小数，`f"{name:>10}"` 右对齐。表达式里不要塞复杂逻辑。

#### 3. 多行字符串与转义

- **这是对照型知识**：不要背定义，直接列一张表——左边写 A，右边写 B，比较「适用场景 / 代价 / 什么时候不能用」。
- **落地**：在「用 += 和 StringBuilder 各拼接 1 万次，记录耗时」里各用一次，让两者的差异产生可观察的结果。
- **验证**：能说出「如果我选错了会怎样」，说不出来就还没懂。

#### 4. 字符串与列表互转

- **这是对照型知识**：不要背定义，直接列一张表——左边写 A，右边写 B，比较「适用场景 / 代价 / 什么时候不能用」。

## 九、卡住时的排查顺序

| 现象 | 最可能原因 | 第一步查什么 |
| --- | --- | --- |
| 程序起不来 / 报错 | 短字符串拼接 JVM 会自动优化，长循环不会 | 先读完整报错，找到第一个 `Caused by` 和自己写的类名 |
| 结果不对但不报错 | 输入不符合预期，或边界没处理 | 在关键位置打印中间值，确认数据在哪一步变错 |
| 照抄示例也跑不通 | 版本/依赖/环境不一致 | 对比版本号；用干净目录重跑一次 |
| 看不懂报错 | 英文术语不熟 | 把报错原文粘到搜索引擎，加上语言和框架名 |
